# Mobile Google login

The mobile client gets a short-lived login challenge from `POST /api/auth/challenges`, passes its exact nonce into a fresh Google native sign-in, and exchanges the returned ID token at `POST /api/auth/exchange`. The backend keeps verifying the token signature, issuer, configured audience, expiry, and exact nonce claim. The app never identifies an account from Google profile fields.

`react-native-nitro-google-signin` 2.3.0 uses Android Credential Manager and the Google Sign-In iOS SDK. The adapter reconfigures the native module with each server nonce and uses `presentExplicitSignIn()` for both platforms. It deliberately avoids iOS `signIn()` / cached-token reads, which may restore an ID token issued before the current challenge. The installed native source passes configured nonce text through unchanged; the returned ID token goes only to the backend exchange.

Set `EXPO_PUBLIC_API_BASE_URL` to the backend origin, plus `EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID` on both platforms and `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` on iOS. These are public OAuth client identifiers, not secrets. Register Android package name plus development signing SHA-1 in Google Cloud, and register the iOS bundle ID and reversed client URL scheme. `app.config.js` adds the Google config plugin when the iOS client ID is configured. Use the Google Services files only if the project chooses that configuration route; this implementation uses explicit environment client IDs. No client secret, profile data, ID token, or bearer session belongs in app config or logs.

Native dependencies are `expo-secure-store`, `react-native-nitro-google-signin`, and `react-native-nitro-modules`. They require an Expo development/native build; Google login is not available in Expo Go. `src/auth/secureSession.ts` binds Expo SecureStore to the serial session store; `sessionStore.ts` remains dependency-injected for Node race tests. The controller restores identity through `/api/me`, persists an exchanged session only if the sign-in attempt is still current, and rejects a delayed exchange after cancellation or logout. A 401 clear notifies the controller. Logout clears this device's session when storage is available even if offline and reports that server revocation is unconfirmed; secure-storage failures keep the session and show a retryable sign-out error.

Run `npm test` and `npm run typecheck` in `apps/mobile`. These validate orchestration and storage races with fakes; they do not establish native behavior or provider configuration. Real acceptance still requires a configured Google project, a development build, and login/cancel/restart/logout checks on Android and iOS devices. No credentials are committed here.

References: [Expo Google authentication](https://docs.expo.dev/guides/google-authentication/), [Android Credential Manager Sign in with Google](https://developer.android.com/identity/sign-in/credential-manager-siwg-implementation), [Google Sign-In iOS SDK releases](https://developers.google.com/identity/sign-in/ios/release), and [Nitro Google Sign-In usage](https://react-native-nitro-google-sign-in.github.io/docs/guide/usage/).
