# Activity exploration impact

Activity impact is a comparison of retained, successfully matched activity history in one explicitly selected OSM dataset. It does not claim exact first-visit timestamps: activities are ordered by recorded date ascending, then internal activity ID ascending for same-day ties. The web explains that same-day ordering is approximate and that importing/deleting history can change these comparisons. Original samples/timestamps and existing completion rules remain unchanged.

`GET /api/activities/{activity_id}/impact?dataset_id=...&rule=normal|strict&page=1&page_size=50` requires the owner bearer token. Absent/other-owner activities return the same 404 before geography lookup. Dataset/version, coverage revision/readiness, activity ID and rule are echoed. Dataset IDs and all BIGINT identifiers are strings. Paging is 1-based, maximum page 1,000,000 and page size 100. A repeatable-read snapshot and existing 1.5-second statement timeout bound each query. No writes, extra matching jobs or migration are needed.

Live support requires exact account/source/revision/dataset contribution, successful current source, matching successful run and successful job. Multiple sources for one activity are a distinct node union. Earlier activity support forms `before`; adding the selected activity forms `after`. Later activities do not reduce historical gains. New GPS nodes are selected-activity nodes absent from `before`. A street advances when its `after` count exceeds `before`; it completes when `before < threshold <= after`, under the requested normal/strict rule. Completion is a subset of advancement. Manual labels never add GPS visits or completion credit.

The response has `activity_id`, `dataset_id`, `dataset_state`, `rule`, `coverage` (existing DatasetCoverage), `history_status=ready|unknown-dates|history-limit|missing-provenance`, nullable `supported_nodes`, `new_nodes`, `streets_advanced`, `streets_completed`, paged `streets`, `page`, `page_size`, and nullable `total`. Every street has exact `street_id`, `city_id`, `dataset_id`, `name`, `city_name`, `eligible_nodes`, `supported_nodes`, nullable `new_nodes`, `before_nodes`, `after_nodes`, `completed_by_activity`, and ready-only current `current_nodes`, plus original eligible-node bounds `[west,south,east,north]` for map focus. Ordered stably: completed-by-activity first, advanced second, revisited third, then city/street name and street ID. Summary totals cover the full affected result before paging; unique new-node totals do not double count nodes shared by streets.

Only streets actually supported by this activity appear. When coverage is pending/failed, all metrics and total are null and the street list is empty. An activity without successful source provenance has `missing-provenance` and unavailable metrics, even if the account's empty coverage is ready. History metadata is bounded to 10,000 distinct owner activities total, including contributing activities in this dataset and the selected activity. Validate ISO calendar dates in Python; any unknown/invalid date in contributing history or exceeding this bound makes historical metrics null with an explicit history status. Ready activity-supported/current-street counts and affected street links remain available in those cases. Do not silently discard undated activities or credit the selected activity as first. Empty valid matched support is ready zero impact.

The shared client loads an independently paged impact resource after activity detail using generated backend types. Account/activity/dataset/rule/request and progress-revision fences prevent late detail/pages from restoring stale results. Deletion, manual correction and completed imports refresh selected activity impact; revision changes while paging restart page one. The web shows exploration totals above optional recording diagnostics, explains repeat-only or unavailable results, and allows retry and additional street pages. Selecting a street focuses its original bounds and highlights its current bounded viewport geometry, with an explicit notice if display geometry is absent/limited; street details remain accessible. Old activity/street selection and account changes clear highlights. Map geometry remains display-only and inherits existing limits.
