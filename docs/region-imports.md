# Additional public OSM regions (T04 / D11–D13 / D37)

This extension adds operator-supplied regional OSM XML extracts, durable import/backfill processing and browser region discovery. It preserves original activity samples, street rules and existing complete Gent geography. It does not add PBF, arbitrary browser geography uploads, automatic OSM downloads, replacement activation, provider adapters or deployment.

## Operator import and recovery

An operator CLI submits a local public extract with an explicit region key, selected administrative relation IDs and source/query completeness evidence. Only complete extracts activate a first region version; sampled inputs and later versions of an active region remain staged as before. No account can mutate shared geography through an HTTP endpoint.

Submission snapshots bytes into a private durable map-import storage root, using a random/hash-qualified object key, before creating a global durable task. Tasks store checksum, snapshot timestamp, selected relation IDs, coverage mode/evidence and eligibility-rule version, never caller filesystem paths. Identical region/checksum/coverage-mode/selected-relations/rule submissions reuse one task/dataset; changed bytes, coverage mode or selection form a distinct staged/import identity. A failed task can be explicitly retried. Operator status reports safe error codes and phase/checkpoint, without paths, tokens or GPS.

Bounds: XML at most 64 MiB; at most 50 selected cities, 250,000 nodes, 100,000 ways and 1,000,000 way/member references. Validate input and XML limits before storing geography. Preserve administrative holes/components, eligible original nodes, exact street-name grouping, checksum and source timestamp. Recheck the immutable stored snapshot checksum before processing. Reject malformed/incomplete extracts with bounded safe errors. No external URL is accepted.

A global task has `queued`, `running`, `backfilling`, `succeeded` or `failed` state, capped attempts and a lease token/deadline. Existing account jobs retain their owner-qualified schema; system tasks do not use synthetic accounts. The ordinary worker processes global tasks when no account job is ready, preserving interactive import priority. Each claim/checkpoint/acknowledgement is token/deadline-fenced. Geography insertion, first-region activation and task transition/backfill initialization commit atomically; interruption rolls back partial geography and retries the immutable extract from the beginning. This is restart recovery, not an intra-file parser checkpoint. Staged/sampled imports finish without backfill or activation.

## Existing activity backfill

Every newly activated complete region creates durable matching work in the same commit. The task stores a nullable signed-BIGINT source cursor and queues at most 20 current successful sources per step through existing account-qualified `queue_source_coverage`, at low backfill priority. Cursor advancement and queued jobs commit atomically. Advance over inspected deleted/changed rows as well as queued rows; owner guards and exact source revision/activity revalidation preserve deletion/account/lease fences. Per-owner transactions must not hold another owner's locks. Deleted owners/sources are safely skipped under their guards. A live owner transaction failure rolls back its cursor/job writes and leaves the task incomplete for bounded retry, followed by explicit operator retry after exhaustion; it must never be silently skipped. Task success requires every surviving scanned source to have current matching work queued or already qualified. Revalidate and queue a changed successful source using its current revision/activity. Deleted sources are never restored or uploaded again.

All activation paths, including retained direct `import_osm_xml` calls, initialize durable backfill and share the same global advisory-lock fence with normal active-dataset enumeration: source enqueue holds a shared transaction lock before enumerating datasets; activation takes the exclusive lock without holding owner locks. A successful ingestion therefore either precedes activation and is scanned by backfill, or sees the active region and queues its own match. Account-job locks keep their existing guard/job/source/run/activity ordering. Concurrent workers cannot advance one task with a stale lease; interrupted pages can replay idempotently. Missing current runs keep coverage pending until matching finishes; task success means queueing finished, not that account matching is complete.

Contributions remain dataset-qualified. Overlapping regions may contain the same OSM nodes, but each city's denominator/progress belongs to its selected dataset. Unsupported samples count once outside the union of active city boundaries. Existing Gent coverage, manual labels, source originals, timestamps and IDs remain unchanged. No aggregate sum is advertised as distinct world coverage.

## Browser discovery contract

Authenticated `GET /api/datasets?rule=normal|strict&page=1&page_size=20&q=` returns `DatasetPage`: echoed rule/page/page_size, total and stable region-name/ID ordered `items`. Page size is at most 20; page is at most 1,000,000; literal case-insensitive region query is at most 200 characters. List only active complete datasets. Each `DatasetItem` extends the existing lifetime `ProgressDataset` fields with `bounds=[west,south,east,north]`. Null progress while pending/failed retains existing semantics. Queries use owner identity, one repeatable-read snapshot and bounded statement timeouts; source/GPS data is not returned. Existing map/progress APIs keep their caps and response behavior.

`GET /api/datasets/{dataset_id}?rule=...` returns the exact active complete selected item or 404, allowing loaded selection refresh independent of discovery-page position. `CityItem` adds original city `bounds` to existing city-list responses. Generate shared types from the implemented backend before client wiring.

The shared city store uses paged discovery when enabled, retaining the legacy progress-only path for native screens. Browser region search/load-more and selected dataset refresh are account/rule/request-fenced. Region/city clicks center the map on returned public bounds; a focus intent must survive switching between regions repeatedly but never replay after sign-out/account replacement or a stale response. City/street pages remain explicit-dataset and lifetime scoped; activity filters/Explore coverage scope and route drafts are preserved. Show matching pending/failed text rather than zero completion. Existing browser activities/import/planner behaviors remain compatible.

## Acceptance

Use synthetic files/accounts for regression checks: interrupted import rollback/retry, stale task lease/acknowledgement, durable cursor restart, source ingestion concurrent with activation, deletion/revision/retry/account races, overlapping regions/holes, idempotent submissions, malformed/bounded XML, staged replacements, unchanged Gent and original GPS. Verify catalog paging/search beyond 20 regions, selected-region refresh, owner isolation, pending/null progress, city/region map focus and late account responses. Run disposable PostGIS, shared/mobile tests/typecheck/generated checks, web units/build/production Chrome and both JavaScript exports. Independently review backend and client/web before merging/pushing and verify hosted CI. Load one second public city into the persistent preview using documented source metadata; validate via actual HTTP/browser and API/worker/PostgreSQL restart. Native acceptance remains assigned separately.
