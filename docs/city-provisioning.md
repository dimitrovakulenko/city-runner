# Activity-triggered city provisioning

Worldwide availability is a product requirement. Geography is indexed on demand, shared across accounts: the first retained recorded activity in Antwerp requests Antwerp, without operator-supplied city IDs. This replaces manual town onboarding; it does not require a planet database on a developer laptop. A country policy, valid OSM boundary and complete extract must exist before its city can report completion. Unsupported places and provider failures remain explicit; this development adapter is not worldwide release acceptance.

## Discovery and privacy

Only original finite GPS samples select geography. Never interpolate between samples, join track gaps, replace originals or send samples, activity/owner identifiers, routes or derived bounding boxes to an external provider. Fetch the fixed public Geofabrik extraction polygon catalog once and use it locally as a coarse candidate-country index; buffered extraction polygons are not authoritative country boundaries. Fetch country-wide municipal relation ID/name/public-bbox catalogs using fixed ISO country and versioned administrative-level policy queries. Check candidate bboxes locally, fetch complete city data by public OSM relation ID, and verify actual boundary containment locally. A candidate bbox alone must never claim a sample belongs to a city.

Country policies explicitly select municipal administrative levels; there is no universal level-eight fallback. Ship documented policies and support server-configured additions. Unknown policies, missing boundaries, uncovered samples, ambiguous catalog structure and exceeded bounds stay visible. This is automatic city selection within available policies, not manual city registration. Already-active original relation IDs reuse existing datasets, including Gent and Brugge.

Policy expansion must also discover cities for retained recordings previously marked unsupported, without uploading their originals again. Compare stored candidate-country links with the current validated country task identities (including levels, profile and query version). A terminal request with a newly supported missing country, or any request linked to an obsolete country task, is pending until bounded owner/source/revision-fenced rediscovery. Clear only its private discovery links, cursors and errors; preserve original recordings, shared successful public tasks, active geography and contributions. In-progress country pagination must not repeatedly reset merely because a later country has not been linked yet. Activity detail/list and matching readiness use the same policy-change condition as preparation status. Deleted or revised sources must never be enrolled from stale candidates. API and worker use the same effective policy configuration. World-catalog refresh and replacing existing active geography are separate work.

### Shipped municipal policies

The development adapter now ships 32 explicit country policies. These select municipal authorities, including rural municipalities, rather than built-up settlement outlines. They enable discovery; they do not certify that OSM contains complete boundaries or that every municipality fits the provider bounds.

| OSM administrative level | ISO country codes |
| --- | --- |
| 5 | LV |
| 6 | CO, MX, NZ, PH |
| 7 | DK, EE, GR, JP, NO, PL, PT, SE |
| 8 | AT, BE, BR, CH, CL, CZ, DE, ES, FI, FR, HU, IT, LU, NL, PE, RO, SI, SK, US |

Policies follow the [OSM country table](https://wiki.openstreetmap.org/wiki/Tag:boundary%3Dadministrative#Country_specific_values_of_the_key_admin_level%3D*) and country guidance for [Japan](https://wiki.openstreetmap.org/wiki/Japan_tagging#Boundary), [Poland](https://wiki.openstreetmap.org/wiki/Poland/Podzia%C5%82_administracyjny), [Hungary](https://wiki.openstreetmap.org/wiki/Hungary/Boundaries), [Greece](https://wiki.openstreetmap.org/wiki/Greece/Administrative_Divisions) and [Peru](https://wiki.openstreetmap.org/wiki/ES:Per%C3%BA/Convenciones). Japan level 7 includes Tokyo special wards, while level 8 subdivisions of designated cities are excluded. Peru uses municipal districts.

[US level 8](https://wiki.openstreetmap.org/wiki/United_States_admin_level) deliberately offers partial incorporated-municipality coverage; exceptional cities such as New York City and Washington, DC and unincorporated territory remain unsupported. Do not broaden it to every county or township. Canada, the UK, Ireland and South Africa still need qualified subnational or municipal-type selectors: a country-wide union of their numeric levels would include nonmunicipal authorities or subdivisions. Other unlisted countries remain explicitly unsupported unless an operator supplies a validated `CITY_ADMIN_LEVELS` policy. No generic level is inferred.

The development provider is explicitly enabled by `CITY_GEOGRAPHY_PROVIDER=overpass`; disabled mode preserves existing file imports and known-region matching. Public URLs are fixed or trusted server configuration, never supplied by users. Query bodies contain only public country codes/policy levels or relation IDs. Reject redirects, invalid/truncated/oversized responses and Overpass error/remark responses, including HTTP 200 partial results. A city query must prove a generated city area exists and include its full boundary and every named highway in that area; incomplete data must not activate a complete denominator. Retain immutable snapshot checksum, query/policy evidence and source timestamp.

Bounds: catalog JSON at most 16 MiB, 10,000 extraction features, 50,000 municipal candidates per country; country policy levels 2–10; city extracts inherit the 64 MiB/parser bounds of the region-import contract. One database-wide admitted request at a time, at least two seconds between requests, at most 100 requests and 256 MiB reserved transfer per UTC day. Network attempts have a fixed total timeout below the task lease, no in-request retries and capped durable retry/backoff. Tasks reserve the maximum response size before admission, preventing concurrent daily-budget overshoot. Cache successful public results durably. Public Overpass is a bounded development adapter; public release needs an approved hosted data provider or owned extract service, not dependence on donated instances.

## Durable work and matching

Create one owner/source/revision-qualified preparation request in the successful ingestion transaction when discovery is enabled. When enabling discovery over existing data, the worker enrolls at most 20 missing current successful retained sources per step; missing requests count as pending until enrollment, not ready. Account/source deletion cascades its private request/link rows; no global public task stores private GPS or owner identity. Global public catalog/country/city work has stable dedupe keys, capped failure attempts, lease token/deadline and durable safe errors. Successful waits/checkpoints do not consume a failure budget. Snapshot/network execution holds no owner/task database lock. All commits, retry/acknowledgements and expired recovery are lease/revision fenced. Deleted items and accounts remain terminal; public work already accepted may finish safely without reimporting a deleted source.

Private preparation phases are queued discovery, waiting for public catalog/country/city work, and ready/failed/unsupported. Any failed required dependency yields failed; otherwise outstanding work yields pending. After all available-policy candidates have been checked against actual boundaries, remaining uncovered samples or unknown policies yield terminal unsupported; fully resolved discovery yields ready. Unsupported is terminal for discovery but retains explicit unsupported diagnostics and never fabricates a city denominator. Later applicable city activation reconciles these diagnostics against current original samples and active boundaries, clearing obsolete unsupported status. Activity `processed` waits for preparation to be ready or terminal unsupported and for all current applicable matching jobs; failed/pending discovery keeps it false. Known active-city coverage remains independently usable while other geography is preparing or unsupported. Shared public results are useful beyond a single request; task completion never revives an absent/revised private source.

The worker advances bounded public and owner preparation steps alongside existing jobs. Country/city requests from concurrent accounts reuse one task. City extracts enter the existing immutable map-import/first-activation pipeline; map import success, account matching and preparation readiness are distinct. Preparation becomes ready only after local city discovery is complete and applicable city imports are active; activity readiness also waits for its current matching jobs. A city activation automatically queues relevant retained sources, including requests accepted before activation/restart. Complete shared city geography and per-owner contributions stay separate. Retries reset only failed work referenced by the authenticated owner, never arbitrary public IDs or another owner's private rows.

Spatially restrict matching to datasets whose city boundary is within 25 m of an original sample, preserving boundary-near matches and overlap. Use a conservative indexed envelope for pruning, then original-sample qualification; unknown/legacy envelopes must not create false-negative skips. No interpolation credit is added. Persist or consistently derive applicability so activity, dataset, sync status, retry, filtered progress and exact recording-group readiness require current runs only for applicable datasets. Unrelated city activation must not make an activity pending. Unsupported samples remain counted once against the union of active complete boundaries. Preserve owner-before-job/source/activity locks, global activation/enumeration fencing, atomic source cursor/job checkpoints and manual labels. Backfill skips irrelevant sources without GPS/job fan-out.

## Authenticated status and retry

`GET /api/coverage-preparation` returns `{enabled, state, pending_sources, failed_sources, unsupported_sources, cities, cities_truncated}`. State is `ready`, `pending`, `failed` or `unsupported`; failed takes precedence over pending, unsupported is not zero completion. Counts cover only retained successfully imported current sources belonging to the current account. Return at most 20 distinct requested cities ordered by public name/relation ID. Each city is `{osm_relation_id: string, name: string, state: queued|fetching|importing|ready|failed, error: string|null}`. No provider URLs, storage keys, country-selection coordinates, other-owner demand or source paths appear. Requests use owner fencing, bounded work and `Cache-Control: no-store, private`.

`POST /api/coverage-preparation/retry` returns 204; requeues bounded failed preparation work for the current owner and its referenced failed public tasks. Existing pending/ready work is idempotent. Retry never uploads files or restores deleted sources. More than one page of failures is handled through repeated bounded calls, without a broad global reset.

Preparation writes/public task transitions advance the transactional foreground change token. Browser foreground refresh includes preparation status, remains nonoverlapping and retains filters, selection and route drafts. The UI explains city discovery, “Preparing Antwerp coverage”, failure/retry and unsupported geography. Generate implemented backend API types before client wiring; account replacement/logout fences late results and retry responses. Native execution remains with the separate team.

## Acceptance

Synthetic tests cover country clipping overlap/holes, multiple cities, city-bbox false positives, level policies/unsupported places, immutable original bytes and timestamps, complete-area proof, provider quotas/partial/corrupt responses, deduplication across owners, source deletion/retry races, stale leases, restart and spatial readiness. Actual localhost HTTP/browser verification uploads an Antwerp activity and observes automatic public-country discovery/city fetch/import/matching without an operator city ID. Use only synthetic GPS; do not download a planet/country PBF or install large SDKs. Independently review backend and client/web, run PostGIS/generated-type/shared/web checks and both JS exports, merge/push and verify hosted CI. The owner subsequently authorized proceeding with Hetzner development hosting. Deploy only to the selected project/configuration and verify actual HTTPS, authentication, import/restart and recovery before claiming hosted acceptance; local checks alone do not establish it.
